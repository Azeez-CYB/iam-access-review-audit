# IAM Access Review and Audit

A Python-based Identity and Access Management (IAM) project that analyses synthetic user-access records to identify potential access-control weaknesses and support audit reviews.

## Project Overview

Organisations need to ensure that users have appropriate access to systems and that access rights are reviewed regularly. Excessive permissions, dormant accounts and access that remains after an employee leaves can increase security and compliance risks.

This project simulates an IAM access review using Python and pandas. It compares user permissions against a defined role-permission baseline and generates findings for further investigation.

**Project status:** Working prototype using synthetic data.

## Objectives

- Identify potential access-control weaknesses.
- Validate permissions against role-based access control (RBAC) rules.
- Flag accounts requiring further review.
- Generate structured findings to support audit documentation and remediation tracking.

## Security Checks

The project includes checks for:

- **Dormant accounts:** Accounts with no recent login activity, based on the configured review threshold.
- **Leaver accounts:** Accounts flagged for review because the associated user has left.
- **RBAC exceptions:** Permissions that fall outside the defined baseline for a user's job role.
- **Privileged access:** Privileged permissions that may be missing required approval.
- **Segregation of duties (SoD):** Potential conflicts between permissions that should be separated.
- **Role baseline issues:** Accounts whose roles do not have a corresponding entry in the role-permission matrix.

Findings identify potential issues for investigation. They do not automatically prove that a security breach has occurred or that access must be removed.

## How to Run the Project

### 1. Prerequisites

Install Python 3 and pip.

### 2. Install the dependency

Open Terminal in the project folder and run:

```bash
python3 -m pip install pandas
```

### 3. Run the review

```bash
python3 iam_access_review.py
```

The script reads the sample access register and role-permission matrix, performs the configured checks and writes the results to `access_review_findings.csv`.

### 4. Review the results

Open `access_review_findings.csv` in a spreadsheet application to review the generated findings.

## Remediation and Governance

The findings can be used to support a documented review process. Example follow-up actions include confirming whether an account is still required, validating permissions with an application owner, checking leaver access revocation and obtaining evidence of privileged-access approval.

The remediation tracker is maintained separately and is not automatically populated by the current script.

## Limitations

- Uses fictional sample records rather than live identity systems.
- Does not connect to Active Directory, Entra ID or an enterprise IAM platform.
- Identifies potential issues for human review rather than making access changes.
- Findings depend on the accuracy of the input data and configured rules.

## Future Improvements

- Automate the creation of remediation records from audit findings.

## Ethical Use

This project is designed for learning and portfolio demonstration. All sample data should remain fictional. No confidential employer information or real user-access records should be included.

## Testing and Validation

The project was tested using synthetic user-access records to validate its access-control checks.

### RBAC Exception Test

- **Test scenario:** Added a permission outside the defined role-permission baseline for a synthetic user.
- **Expected result:** The script should flag the permission as a potential RBAC exception.
- **Actual result:** The script generated a `Permission outside role baseline` finding.
- **Outcome:** Passed.

This test demonstrates that the script can identify permissions that do not match the configured role baseline. Findings require further review before any access changes are made.
